# UniLab 设计规范

**版本** v1.0 · **状态** 可用于生产借鉴 · **适用范围** 中后台管理系统（信息密集型）

---

## 〇 这份规范是什么

它不是凭空设计的一套「理想设计系统」，而是从「具身智能实训基地管理系统」5 份已交付的高保真原型中**反向抽取的事实基线**，再经无障碍实测校正后固化下来的。

| 基线来源 | 贡献 |
|---|---|
| `course-management.html` | 布局骨架、全部基础组件、表格/抽屉/模态/Toast |
| `course-management-roles.html` | 角色感知模式（角色切换器、只读徽标、导航裁剪） |
| `training-management-roles.html` | 冲突拦截与排队反馈 |
| `device-management-roles.html` | 遥测/急停等高危操作的视觉分层 |
| `跨子系统RBAC权限总表.html` | 权限矩阵四态符号体系 |

### 交付资产

| 文件 | 用途 |
|---|---|
| `ui-kit.css` | **可直接引用的样式库**。17 组令牌 + 26 类组件，换肤只改 `:root` |
| `设计规范.html` | **可视化活文档**。色卡/字阶/组件实例/代码片段一键复制 |
| `设计规范.md` | 本文件。文字版规范，供评审与交接 |
| `starter-template.html` | **新项目起步骨架**。已内置 App Shell + 角色感知 + 冲突拦截 |

> 移植成本：复制 `ui-kit.css` + `starter-template.html` 两个文件即可起步，无构建依赖、无框架绑定。

## 一 设计原则

五条原则是所有取舍的裁决依据。方案有争议时，按序号优先级判断。

| # | 原则 | 含义 |
|---|---|---|
| ① | **信息密度优先** | 用户是每天用 8 小时的专业角色，不是首次访问的访客。宁可字号小 0.5px，也要让一屏承载更多决策信息 |
| ② | **状态即色彩** | 颜色只服务状态语义，不做装饰。六个语义色各有唯一含义，新状态必须归入现有语义，不得引入第七种色相 |
| ③ | **权限可见化** | 用户看不到的功能不该出现在导航里；能看不能改的必须有只读锁标。权限差异是**界面结构**的一部分，不是运行时报错 |
| ④ | **危险操作前置拦截** | 冲突、越权、安全风险必须在提交**前**用红框+文案+禁用按钮拦截，并给出可行替代方案。不允许「点了才报错」 |
| ⑤ | **需求可追溯** | 每个界面区块标注对应需求编号（如 `FR-CUR-0304`），设计与文档双向可查 |

### 2.4 语义色（双值制）

> **这是本规范最关键的一条修正。** 语义色有两套值：饱和值用于图形与大字号；`-text` 变体用于小字号。原型直接把饱和色用在 soft 底上做 12px 文字，7 处不达 WCAG AA，UI Kit 已全部修正。

| 语义 | 饱和值（图形） | soft 底 | 原型实测 | **文本安全变体** | 修正后 |
|---|---|---|---|---|---|
| green 正常/通过 | `#16A34A` | `#ECFDF5` | 3.2:1 ✗ | `--green-text #15803D` | **4.8:1 ✓** |
| amber 警告/只读 | `#D97706` | `#FEF3C7` | 2.9:1 ✗ | `--amber-text #B45309` | **4.5:1 ✓** |
| red 故障/冲突 | `#DC2626` | `#FEF2F2` | 4.4:1 ✗ | `--red-text #B91C1C` | **5.9:1 ✓** |
| sky 进行中/信息 | `#0EA5E9` | `#E0F2FE` | 2.5:1 ✗ | `--sky-text #0369A1` | **5.2:1 ✓** |
| violet 特殊/科研 | `#8B5CF6` | `#F5F3FF` | 3.9:1 ✗ | `--violet-text #6D28D9` | **6.5:1 ✓** |
| gray 停用/归档 | `#64748B` | `#F1F5F9` | 4.3:1 ✗ | `--gray-text #475569` | **6.9:1 ✓** |
| 侧栏分组标题 | `#475569` on `#0F172A` | — | 2.4:1 ✗ | `--sidebar-label #94A3B8` | **6.9:1 ✓** |

### 2.5 语义映射约定（不得自行扩展）

| 色 | 业务语义 | 本系统实例 |
|---|---|---|
| green | 正常 · 在线 · 通过 · 已完成 | 设备在线、评测通过、课程已发布、进度达标 |
| amber | 警告 · 待处理 · 受限 · 只读 | 待审批、维护中、教师只读锁标、权限 ◐ |
| red | 故障 · 冲突 · 急停 · 禁止 | 排课工位冲突、设备故障、急停按钮、越权拦截 |
| sky | 进行中 · 信息 · 仿真 | 实训进行中、仿真环境、提示信息 |
| violet | 特殊 · 科研 · 竞赛 | 科研项目、竞赛专享通道 |
| gray | 停用 · 归档 · 无 | 课程已归档、设备报废、权限 ✗ |

## 三 排版

中文优先字体栈：`"Noto Sans SC","PingFang SC","Microsoft YaHei",system-ui,…`
基准 **14px / 行高 1.5**。字号阶保留 0.5px 步进（13.5px）—— 这是信息密度与可读性的取舍，非笔误。

| 令牌 | 规格 | 用途 |
|---|---|---|
| `--fs-display` | 28px / 700 / lh 1 | KPI 数值 |
| `--fs-title` | 22px / 700 | 页面主标题 h1 |
| `--fs-subtitle` | 16px / 600~700 | 弹层与抽屉标题 |
| `--fs-card` | 15px / 600 | 卡片标题 h3 |
| `--fs-base` | 14px / 400 / lh 1.5 | 正文基准 |
| `--fs-ui` | 13.5px | 按钮、导航项、表格单元格 |
| `--fs-sm` | 13px | 次级说明、筛选药丸、搜索框 |
| `--fs-label` | 12.5px / 600 | 表头、KPI 标签 |
| `--fs-hint` | 12px / lh 1.6 | 提示、脚注 |
| `--fs-micro` | 11.5px / 600 | 芯片、只读徽标 |
| `--fs-nano` | 11px / +1px 字距 | 侧栏分组标题（大写） |

**应当**：正文 `--body`、标题 `--ink`、说明 `--muted`；表格统一 13.5px、表头 12.5px/600；脚注行高放宽 1.6。
**禁止**：新增字号档位；正文用 700 字重（强调改用 600 或颜色层级）；用 `--faint` 承载可读文字。

## 四 间距 · 圆角 · 层高

**间距**：4px 基准栅格 `--sp-1…8` = 4/8/12/16/20/24/32/40，允许 2px 半步用于图标光学对齐。
常量：内容区内边距 24px · 卡片栅格间距 16px · 卡片头 16/20 · 卡片体 18/20。

**圆角**（按元素体量递增）：`--r-xs 6`（芯片）· `--r-sm 8`（按钮/输入/药丸）· `--r-md 10`（分段控件/toast）· `--r-lg 12`（卡片/表格）· `--r-xl 14`（模态）· `--r-full`（标签）。

**层高 5 级**：

| 级 | 令牌 | 用于 |
|---|---|---|
| L1 | `--shadow` | 卡片、KPI、表格 |
| L2 | `--shadow-pop` | 悬浮卡、下拉 |
| L3 | `--shadow-drawer` | 右侧抽屉 |
| L4 | `--shadow-toast` | 轻提示 |
| L5 | `--shadow-modal` | 模态框 |

**固定布局尺寸**：侧栏 248px（不折叠）· 顶栏 64px · 抽屉 420px · 模态 560px（均 max-width 92vw）· 紧凑控件 32px · 标准按钮 38px。
**z-index**：sticky 20 / dropdown 30 / mask 40 / drawer 41 / modal 50 / toast 60。

## 六 交互模式（最值得跨项目借鉴的部分）

比组件高一层的可复用资产。以下五个模式是本项目原型真正的差异化价值。

### P1 · 角色感知界面 ★ 最高复用价值

同一套界面按角色裁剪，权限差异体现在**结构**而非报错。

- **导航裁剪**：无权限模块直接从侧栏移除（学生看不到「机器人绑定」），而不是点进去报 403
- **默认落地页差异化**：管理员→总览，教师→课表编排，学生→我的进度。开屏即主战场
- **只读锁标**：能看不能改的区块，标题右挂 `.ro-badge.lock`，动作按钮同步禁用
- **动作语义降级**：同一按钮，管理员是「保存排课」，教师变「提交申请」
- **权限自查口**：顶栏常驻「权限对照」入口，任何人可自查边界，减少客服问询

```js
const ROLES = {
  admin:   { defaultView:'overview', nav:['overview','curriculum','schedule','binding'],
             perm:{ editSchedule:true,  publishTraining:true  } },
  teacher: { defaultView:'schedule', nav:['overview','curriculum','schedule','binding'],
             perm:{ editSchedule:false, requestTraining:true  } },
  student: { defaultView:'progress', nav:['overview','curriculum','schedule'],  // 无 binding
             perm:{ editSchedule:false } }
};
// nav 决定侧栏项；perm 决定按钮文案与禁用态
```

### P2 · 提交前冲突拦截

资源类系统（排课、预约、算力配额）的通用范式：**实时校验 → 视觉拦截 → 给替代方案**。

- 选择资源与数量的**同时**发起占用查询，不等提交
- 冲突时：`.conflict` 红框 + 具体数字「需 4 台，仅 3 台空闲」+ 主按钮 disabled
- 必须给**可执行替代方案**（改时段 / 减数量 / 排队），否则用户只能干瞪眼
- 通过时同样给正反馈 `.okbox`，让用户确信系统真的校验过

### P3 · 需求追溯徽标

每个视图右上角标注对应需求编号，设计-文档双向可查。成本一个 chip，收益在评审与验收阶段兑现。

```html
<div class="card-head">
  <h3>课表编排</h3>
  <span class="hint">FR-CUR-0301 ~ 0305</span>
</div>
```

### P4 · 单页多视图

原型阶段用 `.view.active` 切换而非多文件，保证状态连续、便于演示。正式开发替换为路由，结构一一对应。

### P5 · Mock 数据显式标识

页面顶部挂 `.proto-tag` 标明「原型 Mock 数据」；跨系统数据在 `.note` 写明真实来源（如「工位占用需接设备管理 IC-04」）。
评审时挡掉大量「这个数据对不对」的无效讨论；交付研发时，Mock 标识的位置就是**接口对接点清单**。

## 七 无障碍（WCAG 2.1 AA）

### 7.1 UI Kit 已内置

- 统一 `:focus-visible` 焦点环（2px 主色 + 2px 偏移）—— **原型完全缺失，本次补齐**
- 7 个 `--*-text` 安全色变体，全部实测 ≥4.5:1
- 侧栏分组标题由 2.4:1 提亮至 6.9:1
- `prefers-reduced-motion` 动效降级
- `.sr-only` 屏幕阅读器专用类

### 7.2 移植时仍须补齐（UI Kit 覆盖不到的行为层）

| 项 | 要求 |
|---|---|
| 焦点管理 | 模态/抽屉需焦点陷阱、ESC 关闭、打开时焦点转移、关闭后焦点归还 |
| 符号可读性 | 权限矩阵 ✓/◐/✗ 必须配 `aria-label`，纯符号对读屏不可用 |
| 不依赖颜色 | 状态**不可仅靠颜色**传达，冲突态需同时给红框 + 文案 + 图标 |
| 触控目标 | ≥44px。当前 `.pill` 仅 32px，触屏场景须放大 |
| 图表等价 | 雷达图/热力图须提供等价数据表 |
| 键盘可达 | 所有 `onclick` 元素须用 `<button>` 或补 `tabindex` + `role` + 回车响应 |

## 八 跨项目移植清单

| 步骤 | 动作 |
|---|---|
| **1 引入并换肤** | 复制 `ui-kit.css`，**只改 `:root` 令牌层**。换主色需同时改 `--primary`/`-d`/`-soft`/`-border` 四值，并重测白字对比度 ≥4.5:1。组件层不要改 |
| **2 裁剪组件** | 按需删除用不到的组件段（§4~§16 有清晰分节注释）。保留 §1 令牌与 §2 基础层 |
| **3 复用交互模式** | P1 角色感知与 P2 冲突拦截跨领域通用，优先移植。P3 适合有 SRS 的项目，P5 适合原型评审场景 |
| **4 守住无障碍底线** | 小字号一律用 `--*-text` 变体；不得用 `--faint` 承载正文；焦点环不得移除；危险状态必须色+框+文案三重表达 |

### 换肤示例（改为绿色品牌）

```css
:root{
  --primary:#059669; --primary-d:#047857;
  --primary-soft:#ECFDF5; --primary-border:#A7F3D0;
  --blue-text:#047857;   /* 同步 tag.blue 的文本安全色 */
}
/* 白字在 #059669 上 3.9:1 —— 不达标，需改用 #047857（5.1:1）作主按钮底 */
```

## 九 维护约定

1. **令牌层变更** → 必须重跑对比度实测，更新本文档 §2.4 与 `设计规范.html` 的 a11y 表
2. **组件层变更** → 必须同步更新 `设计规范.html` 的实例与代码片段
3. **新增组件** → 先问「能否用现有组件组合实现」；确需新增时同时补入 `ui-kit.css` 分节 + 手册实例 + 本文档 §5 表格
4. **新增颜色** → 默认拒绝。必须归入现有六语义之一
5. **版本号** → 令牌层变更升次版本（1.x），组件层新增升修订号（1.0.x）
